## Architecture Patterns

### Pattern 1: cwt_timed() as a Non-Abstract Peer to cwt()

`cwt()` already calls 6 methods in sequence (lines 158-176 of wavelet.py). `cwt_timed()` repeats the same call sequence with `time_call()` wrapping each step and collects elapsed times into a `dict[str, float]`. It returns `(result, timings_dict)`.

Because `cwt_timed()` calls the same abstract methods as `cwt()`, it inherits correctness from all subclasses without any subclass changes. It belongs on the `Wavelet` base class as a concrete (non-abstract) method, placed immediately after `cwt()`.

**Stage keys (must match D-01 verbatim):** `raw_cwt`, `normalize`, `magnitude`, `edge_trim`, `hop_center`, `downsample`.

```python
# Source: wavelet.py — based on existing cwt() pipeline, lines 158-176
def cwt_timed(self, input_data: np.ndarray[np.floating]) -> tuple[np.ndarray, dict[str, float]]:
    if input_data.shape != self.input_shape:
        raise ValueError(...)

    result, t_raw_cwt     = time_call(self.class_specific_cwt, np.asarray(input_data, dtype=np.float64))
    result, t_normalize   = time_call(self.normalize_by_scale, result)
    result, t_magnitude   = time_call(self.compute_mag, result)
    result, t_edge_trim   = time_call(self.discard_unreliable_coefs, result)
    result, t_hop_center  = time_call(self.extract_hop_center, result)
    result, t_downsample  = time_call(self.downsample, result, self.output_n)

    timings = {
        "raw_cwt":    t_raw_cwt,
        "normalize":  t_normalize,
        "magnitude":  t_magnitude,
        "edge_trim":  t_edge_trim,
        "hop_center": t_hop_center,
        "downsample": t_downsample,
    }
    return result, timings
```

**Import note:** `time_call` lives in `research/utilities/`, not in `subshader`. `cwt_timed()` must either replicate the inline timing pattern (2 lines) or import from utilities. Since `wavelet.py` is a production module that does not import from research tools, the correct approach is to inline the timing using `time.perf_counter` directly in `cwt_timed()`, matching the existing `time_call()` pattern exactly.

### Anti-Patterns to Avoid

- **Importing `research/utilities` from production code:** `wavelet.py` must not import from `research/`. Inline `time.perf_counter` directly in `cwt_timed()`.
- **Modifying `cwt()` itself:** `cwt()` must remain unchanged to avoid performance overhead in production. `cwt_timed()` is the separate instrumented path.
- **Adding GPU-dependent code paths to `cwt_timed()`:** `cwt_timed()` calls the same abstract methods as `cwt()`. GPU vs CPU is entirely determined by which subclass is instantiated — no changes needed in subclasses.
- **Adding a new visual row for NumPy timing:** D-07 explicitly forbids this. Only the comparison table is extended.

## Common Pitfalls

### Pitfall 1: `cwt_timed()` Import Conflict
**What goes wrong:** `time_call()` from `research/utilities` is imported inside `timing.py` and `figures.py` via `from utilities import time_call`. `wavelet.py` has no such import and must not gain one.
**Why it happens:** Developer reaches for the existing `time_call()` helper without checking the module boundary.
**How to avoid:** Use `time.perf_counter()` directly in `cwt_timed()` — same two-line pattern as `time_call()` but inlined.
**Warning signs:** Any `from utilities import` or `import research` appearing in `wavelet.py`.

### Pitfall 2: CuWavelet Not Instantiated for --comparison NumPy Row
**What goes wrong:** `generate_comparison_grid()` instantiates `npwt = NumPyWavelet(...)` unconditionally (line 681) but does not instantiate `CuPyWavelet`. If GPU is available and D-05 requires timing both, the plan must add a conditional `CuPyWavelet` instantiation.
**Why it happens:** The existing code only needed one SubShader backend; the new requirement needs two.
**How to avoid:** Mirror the `TimedSubShader.run()` GPU-availability pattern:
```python
if GPU_AVAILABLE and comparison:
    from subshader.dsp.wavelet import CuWavelet
    cpwt = CuWavelet(sample_rate=sr, input_n=chunk_size, config=wc)
```
**Warning signs:** Only `"SubShader (CPU)"` appearing in the comparison table output regardless of GPU state.

### Pitfall 3: TimingAccumulator Key Collision for Duplicate Labels
**What goes wrong:** When GPU is unavailable, both the "main" SubShader path and the new CPU timing row would use the same label `"SubShader (CPU)"`, causing a `KeyError` in `TimingAccumulator.__getitem__`.
**Why it happens:** D-06 says to use `"SubShader (CPU)"` for NumPyWavelet regardless of GPU availability.
**How to avoid:** When GPU unavailable, the comparison table has only one SubShader entry (`"SubShader (CPU)"`). When GPU is available, it has two: `"SubShader (CPU)"` (NumPy) and `"SubShader (GPU)"` (CuPy). The methods list construction must be conditional on `GPU_AVAILABLE`.

### Pitfall 4: CircularFrameBuffer Shape Mismatch at TimedSubShader Init
**What goes wrong:** `TimedSubShader` currently does not instantiate a `CircularFrameBuffer`, so adding render timing requires creating one. If the buffer's `frame_shape` doesn't match the wavelet's `output_shape`, `push_frame()` raises `ValueError`.
**Why it happens:** The shape must match `wavelet.get_output_shape()` — which is `(num_freqs, target_width)`.
**How to avoid:** Instantiate the buffer after wavelet init: `buf = CircularFrameBuffer(frame_shape=wavelet.get_output_shape(), num_frames=self.num_frames, color_norm_config=ColorNormalizationConfig())`.

### Pitfall 5: Stale Working Tree Changes Break Tests
**What goes wrong:** The `test_normalization_comparability` test (already in the working tree) validates the `PyWavelet.normalize_by_scale()` division. If `wavelet.py` is not in the working tree state when tests run, it will fail.
**Why it happens:** git stash or branch switch could revert the working tree to HEAD where `normalize_by_scale` returns `cwt_coefs` unchanged.
**How to avoid:** Commit D-09 changes before or in the same commit as new implementation work. Tests must pass at every commit boundary.
