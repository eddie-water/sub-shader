This phase restructures a 1191-line monolithic `research/benchmark.py` into three focused modules (`figures.py`, `timing.py`, `wav_export.py`) and splits the 665-line `research/utilities/unit_tests.py` into colocated test files alongside their source modules in `src/subshader/`. **Primary recommendation:** Use `from utilities import ...` in all new `research/*.py` modules (same pattern as current benchmark.py), and write colocated test files with `def test_*()` functions that pytest can collect with `pytest src/`.

### Anti-Patterns to Avoid

- **Changing `from utilities import ...` to `from research.utilities import ...`:** The `research/` directory has no `__init__.py` and is not a package. Bare `from utilities import` works because Python adds the running script's directory to `sys.path`. Changing this would break the import for the new sibling modules.
- **Adding `__init__.py` to `src/subshader/dsp/` test files:** pytest discovers `test_*.py` without `__init__.py`. Adding one could interfere with the installed package namespace.
- **Print-based pass/fail in pytest functions:** The existing `_pass_fail(bool, label)` helper uses print and returns bool — pytest uses assertions. New test functions should use `assert` rather than `_pass_fail`. The `_pass_fail` pattern was designed for the old `run_all()` runner; pytest expects `AssertionError` on failure.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| pytest test discovery config | Custom test runner script | `pytest src/` with zero config | pytest 9.0.2 discovers `test_*.py` by default; no `pytest.ini` needed |
| Shared test helpers | Copy into every test file | `conftest.py` at `src/subshader/` | pytest auto-loads `conftest.py` — shared fixtures and helpers available to all tests in the tree |
| GPU skip logic | `if not gpu_available(): return` at top of test | `pytest.mark.skipif` | Standard pytest skip mechanism; produces `s` in output instead of silently passing |

**Key insight:** The existing `run_all()` function in unit_tests.py is a handrolled test runner that should be replaced by pytest's built-in runner. The test functions themselves are already well-structured; the migration is renaming `assert`-equivalent checks to actual `assert` statements.

## Common Pitfalls

### Pitfall 1: `_pass_fail` vs `assert`
**What goes wrong:** Keeping the `_pass_fail(bool, label)` pattern in colocated test files causes pytest to see the test as always passing (it never raises AssertionError, just prints and returns False).
**Why it happens:** The original unit_tests.py was designed for a custom runner that collects return values. pytest ignores return values.
**How to avoid:** Replace `all_passed &= _pass_fail(condition, label)` with `assert condition, label` in each colocated test function.
**Warning signs:** pytest shows all tests green even when the condition is False.

### Pitfall 2: Import resolution for new research modules
**What goes wrong:** `from utilities import ...` fails in `figures.py` when called from a different working directory.
**Why it happens:** The bare import relies on `research/` being on `sys.path`, which only happens automatically when running `python research/benchmark.py` (Python inserts the script's directory). If `figures.py` is ever imported from outside `research/`, the import fails.
**How to avoid:** Document that all `research/` modules are run from the project root via `python research/benchmark.py`. The dispatcher pattern (benchmark.py as the only entry point) enforces this. Users should never `import figures` directly.
**Warning signs:** `ModuleNotFoundError: No module named 'utilities'` when running from an unexpected CWD.

### Pitfall 3: Test 0 (NumPy vs CuPy) in CI without GPU
**What goes wrong:** The GPU-dependent test (`verify_numpy_vs_cupy`) hangs or produces a misleading skip message when no GPU is available.
**Why it happens:** The existing implementation uses an early return with a print message instead of a proper skip. pytest doesn't know the test was skipped.
**How to avoid:** Use `@pytest.mark.skipif(not gpu_available(), reason="No CUDA GPU available")` on the test.

### Pitfall 4: Matplotlib `Agg` backend initialization order
**What goes wrong:** `matplotlib.use('Agg')` in one module doesn't propagate to modules imported after it if any `plt` operations happened earlier.
**Why it happens:** matplotlib backend must be set before the first `pyplot` import. The original benchmark.py sets it at the top before any other imports.
**How to avoid:** Each new module that uses matplotlib (`figures.py`) should set `matplotlib.use('Agg')` at the top before any `import matplotlib.pyplot as plt`. The benchmark.py dispatcher sets it early too, so running via the dispatcher is always safe.

### Pitfall 5: `wav_export.py` bouncing chirp scope
**What goes wrong:** D-01 says wav_export.py contains "bouncing chirp generation" — but `build_bouncing_chirp` and `build_bouncing_chirp_chunks` actually live in `research/utilities/dsp_helpers.py` and stay there (D-02 locks utilities as-is). The only thing that moves to `wav_export.py` is `export_signal_to_wav` (the 10-line WAV file writer).
**Why it happens:** The context decision may appear to scope bouncing chirp generation to wav_export.py, but that generation code is in utilities and is not being moved. `wav_export.py` calls `build_bouncing_chirp_chunks` from utilities.
**How to avoid:** `wav_export.py` contains only: (1) `export_signal_to_wav` and (2) any top-level function that orchestrates generating and exporting the bouncing chirp WAV. The underlying signal synthesis stays in `utilities/dsp_helpers.py`.

### Colocated Test File Pattern (pytest-compatible)

```python
# src/subshader/dsp/test_wavelet.py
import numpy as np
import pytest

from subshader.config import get_default_config
from subshader.dsp.wavelet import PyWavelet, NumPyWavelet


def generate_tone(freq_hz, sample_rate, num_samples):
    """Generate a pure sine tone at a given frequency."""
    t = np.linspace(0, num_samples / sample_rate, num_samples, endpoint=False)
    return np.sin(2 * np.pi * freq_hz * t).astype(np.float64)


TEST_FREQS = [27.5, 130.81, 440.0, 1000.0, 4186.01, 10000.0]


def test_pure_tone_peak_accuracy():
    """For each wavelet, a pure tone at f should peak at the bin nearest f."""
    config = get_default_config()
    sr = int(config.wavelet.typical_sampling_freq)
    chunk = config.audio.chunk_size

    for cls in [NumPyWavelet, PyWavelet]:
        wt = cls(sample_rate=sr, input_n=chunk, config=config.wavelet)
        freqs = wt.freqs
        for f_target in TEST_FREQS:
            if f_target < freqs[0] or f_target > freqs[-1]:
                continue
            tone = generate_tone(f_target, sr, chunk)
            output = wt.cwt(tone)
            mean_energy = np.mean(output, axis=1)
            peak_bin = int(np.argmax(mean_energy))
            expected_bin = int(np.argmin(np.abs(freqs - f_target)))
            assert abs(peak_bin - expected_bin) <= 1, (
                f"{cls.__name__} @ {f_target:.1f} Hz: peak bin={peak_bin}, "
                f"expected bin={expected_bin}"
            )
```
