## How we are working — preserve this on resume

### Authoring voice rules
- **User authors all final prose. Claude scaffolds, suggests, never writes
  final copy.** All bullets in user's voice (restored from outline).
- **Build upon previous framings, don't restate.** Each section/subsection
  picks up where the prior left off. New section = new teaching beat.
- **Avoid layered forward-pointers.** Don't pre-empt later sections' content.

### Edit pacing rules
- **Propose, don't apply.** Show candidates, wait for explicit pick, then apply.
- **One change at a time.** Even small wordsmith fixes get proposed first.

### Figures
- **Visuals sparingly — only when really helpful.** Bullets carry concepts
  alone unless a visual is genuinely load-bearing.
- 4 figures rendered for §2.4 originally; only 2 retained in the new §2.4
  structure.

### Delivery rules
- **Concise.** No long preambles, no enumerated meta-summaries. Tight bullets/tables.
- **Plain English.** Match the question's level of zoom (one bullet vs whole-doc).
- **Don't surface side-concerns.** Branch state, dirty trees, repo hygiene —
  none of that during authoring sessions. Authoring momentum is the priority.

### Specific patterns the user values
- **Heading-suffix breadcrumbs** (§2.1 The Goal → §2.2 The Tool → §2.3 The
  Basic Case → §2.4 The Geometric Interpretation) — narrative spine.
- **Bold parallel sub-headings** inside one subsection (e.g., **2D** / **3D** /
  **ND**) keep all original bullets without artificial subsection breaks.
- **Cross-section signpost bullets** (a closer that names what the next
  section will pick up) make "build upon, don't overlap" rule visible.
